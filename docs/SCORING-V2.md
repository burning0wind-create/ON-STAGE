# V0.4 作答评分与恢复

评分策略 `answer-performance-v2`。既有训练量表和行为锚点保持原场快照，不把改版后的分数直接与旧汇总方法比较。

## 分数和范围

每题在出题前保存 `scoringTargets`。英语项目讲述考察论证与证据；作品集考察论证、证据、决策；专业问答考察论证、知识、反思；伦理考察贡献与伦理。追问继承原题考察项目。其他能力可记录观察，但不临时加入该题计分范围。

对目标项目，笼统、错答、偏题属于回答质量，可按1–5分行为锚点评价；未问到的项目不补零。每个评分仍须有逐字引文、理由和事实边界。材料自述不等于独立验证。

本题参考分 = 目标项目的有效质量分÷5，按专业量表中相应项目权重归一化至100。环节分先合并同能力独立证据，重复引文不重复计分。语言与摄像头、手部、姿态等信号不进入专业总分。

本场表现参考分 = 已评分环节分按预设环节权重加权，除以已评分环节权重之和。预设英语20、作品集40、专业30、伦理10，仅针对已选择环节；这是产品训练权重，不是院校规定。报告同时展示逐题完成数、待补评数、已评分环节权重和能力覆盖。不因部分观察阻止本场表现分，但不将该分称为完整能力结论。辅助练习不汇总独立作答总分。

院校权重练习分保留原有来源与证据要求，单独请求、单独诊断，不由训练分代替。

## 可靠性

1. 回答先落盘，再开始后台任务；继续下一题不会覆盖后台返回的评分。
2. 核心评分与长篇改写建议分离，减少每次返回规模。OpenAI直连使用严格JSON Schema；其他兼容服务采用JSON与逐项本地校验。
3. 单项校验失败保留其他合格分项；最多三次请求，按缺项和引文错误修复。认证和模型不存在等错误不盲目重试。输出截断时逐步提高预算。
4. 当前DeepSeek接口的思考模式默认开启，可能占用输出预算。核心评分显式关闭该服务的思考模式，保留原模型名称和接口。该字段只发往官方DeepSeek域名，不发往OpenAI或其他兼容服务。
5. 保存超时、网络、HTTP状态、截断、格式、引文等诊断，不保存密钥、服务商原始错误正文或隐式推理内容。
6. 已完成场次可调用 `POST /api/sessions/:id/action`，请求 `{"action":"retry-scores"}`；旧版快照保存在本机 `data/score-revisions/`。只补评缺项，已取得的合格分项不会因后续失败被清空。重启恢复尚在运行或排队的新版任务。
7. 刷新页面不会丢失任务，报告在后台评分后更新。接口持续不可用时保留待补评，不以零分、随机数或字数规则代替评价。

## 验证

97项自动化测试通过，62个JavaScript文件语法检查通过。新增受控测试覆盖：部分观察的范围参考分、单项引文失败隔离、错误重试与保密、认证错误、重复证据、语言和设备隔离、后台保存与继续答题、重启恢复、OpenAI严格结构与截断检测、报告进度。既有测试继续通过。

本机真实模型回归使用用户已提供的五题测试记录及现有配置，三道原先失败题均取得评分；五题专业评分完成，原始问答保持一致。两项表达组织的引文未通过校验时保留其余专业分，不伪造引文。真实记录、密钥和回归输出均留在被Git忽略的本机data目录。

浏览器自动视觉检查因无法确认当前网址而被工具中止；未将视觉检查声称为通过。

技术依据：[OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat)、[DeepSeek思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)、[DeepSeek接口与输出预算](https://api-docs.deepseek.com/api/create-chat-completion/)。
