## 界面规则

1. 选择学校，只显示该校已收录的学院；选择学院，只显示该学院的专业。专业显示代码、名称、学位类型。
2. 已核实的研究方向独立为可选第四级；深圳电子信息仅涵盖部分设计方向，因此该项目必须选择方向。
3. 推免或研究生复试类型下，已明确不适用的专业与方向从列表中筛除。没有核验到某招生类型不等于断言其不招生；来源适用范围会单独提示。
4. 目标年度与目录年份不同，提示参考年份，不把旧资料标成新一年的目录。当前数据年度均为 2027，不自动扩展到后续年份。
5. 改变学校、学院、专业、方向、招生年份或招生类型，清空旧细则、旧权重和对应文件绑定；保留昵称、简历与作品集。
6. 后端按目录 ID 核验层级归属，由目录生成名称和来源快照，不信任客户端提交的自定义专业名称覆盖。
7. 原历史档案不改写；旧草稿若缺少唯一学院/专业 ID，需要重新选择。专业相同但学院、专业代码或方向不同的场次不混合比较。

## 数据维护

`src/catalog.js`：学校目录与校验；`src/catalog-extra.json`：清华与同济的官网核验数据；`public/catalog-state.js`：前后端共享的无副作用联动规则。

每个专业保存真实来源年度、标题、URL、招生类型和核对日期。新增院校时先核对官方硕士招生资料，再补学院和专业 ID；方向保留原代码，不按数组顺序猜测招生代码。目录核实不会自动给学生填写面试细则和评分权重。
