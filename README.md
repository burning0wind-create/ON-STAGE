# 开场 ON STAGE

**多模态整合版（2026-11-01）**：已接入摄像头手部识别、WitMotion BLE IMU、自动分段采集、场次持久化与真实问答同步复盘。使用方法与代码分工见 [多模态整合说明](多模态整合说明.md)。本机可双击`启动整合面试系统.cmd`。


**面向设计学及相关专业学生的多模态升学面试排练与复盘原型。**

每次模拟基于 **个人简历 + 作品集 + 目标院校、专业、年份及招生类型的面试考核细则与评分标准**。从解释作品与研究判断出发，练习英语问答、作品集答辩、设计专业问答和综合素质与设计伦理问答。

> V0.3 · 学校 → 学院 → 专业三级联动，按目标专业重写训练量表；新增官网考核库与可追溯证据账本。未配置模型时可演示流程，不生成虚构评分。

## 核心亮点

- **按院校与专业准备**：按学校 → 学院 → 专业选择目标，研究方向单列，上传简历、作品集、院校细则和评分标准。
- **以单场组织预分析**：按「昵称 + 院校 + 专业名称 + 面试时间 + 第几次模拟面试」建档与缓存；材料与规则指纹防止使用过期计划。
- **七层面试计划**：目标考核、学生与作品画像、环节考官、提问策略、证据缺口、评分框架、面试节奏。
- **按环节模拟**：英语问答 / 作品集答辩 / 设计专业问答 / 综合素质与设计伦理，可选择组合与练习时长。
- **官网考核库**：四校七学院的9条记录（8条官网已核验、1条原文待核验）；按年份、招生类型、学院、专业及方向匹配，保留出处与核验日期。
- **按专业重写评分表**：12种训练量表，包含6项专业能力的权重、行为锚点、证据要求与追问；3项表达反馈独立呈现。
- **有证据的反馈**：借鉴 Interview Master 的五种观察状态、覆盖与质量分离、逐字引文、重复证据去重和反证修正；训练标准与院校标准分开。
- **多模态接入框架**：浏览器语音转写、问题朗读、本机摄像头预览，以及音频、摄像头、手部、眼动状态事件接口。
- **同条件跨次对照**：按院校、专业、招生类型和评分版本等匹配历史，避免把不同标准的分数混在一起。

## 快速开始

环境：Node.js 22.13+。推荐 Node.js 24；Windows、macOS 与 Linux 均可按以下方式启动。

```sh
npm install
npm start
```

打开 http://127.0.0.1:4318 。也可使用 pnpm：

```sh
pnpm install --frozen-lockfile
pnpm start
```

开发与检查：

```sh
npm run dev
npm test
npm run check
```

## 从第一场开始

1. 打开「面试设置」，选择学校、学院、专业及研究方向，填写昵称、招生年份、类型、时间与模拟次数。
2. 上传个人简历和作品集；在「官网考核库」查看匹配规则并载入，或上传、填写对应院校的考核细则与评分文本。可先使用 `examples/` 中的虚构材料测试。
3. 核对来源、年份、招生类型及本场训练评分表。如需按院校权重计算练习总分，确认评分项、依据及权重合计100%。本批库仅湖南大学2027推免有完整20/40/40面试权重可直接载入，其余未公布权重保持空白。
4. 选择本场环节和时长。摄像头、麦克风均按需开启，文字输入始终可用。
5. 开始面试，提交回答，选择继续追问、跳过或进入下一环节。正式模拟中不展示逐题评分和改写示例。
6. 结束后查看覆盖状态、专业质量、独立表达、证据账本、反证修正及1–2项优先改进；导出保留量表与来源快照的 Markdown / JSON。

## 连接真实模型与搜索

复制 `.env.example` 为 `.env.local`，填入你已开通的模型服务配置：

```dotenv
LLM_BASE_URL=你的兼容服务基础地址
LLM_MODEL=你已开通的模型名称
LLM_API_KEY=你的密钥
SEARCH_API_KEY=可选的Tavily搜索密钥
PORT=4318
```

模型三个字段全部配置后启用真实预分析与评价。使用兼容 Chat Completions 的接口；不假定某个特定模型名称。修改环境配置后需重启服务。密钥只留在服务器端，前端不提供密钥存储。

连接模型后，上传材料的文字、院校规则与对话会发送给所选模型服务。搜索仅发送院校、专业、年份等公开检索词。语音转写使用浏览器的识别服务，可能通过浏览器供应商处理音频，需在界面单独勾选。

## 评分与感知边界

- 院校总分只使用本场确认的评分项与权重；训练分采用 ON STAGE 编写的待校准专业量表，不代表官方考试成绩。训练权重不是 Interview Master 或院校发布的权重。
- 面试内部维度、材料审查、笔试和录取总成绩公式分别保存；官网未公布的细项权重不按平均值补齐。同济设计创意原文当前无法读取，条目明确待核验。
- 全部专业能力均已观察且证据充分时才显示完整训练总分；部分观察可有分项质量分，跳过、未考察、证据不足不补零。重复原文不增加独立证据。
- 表达流畅度与专业能力独立；表达反馈不进入专业训练总分。看过改写示例后的练习不作为独立能力成绩。
- 未连接模型、模型响应不合格或没有回答证据时显示待评估，不用连接词数、回答长度或数字数量替代评分。
- PDF 提取文字；扫描件和图片保留原件，需补充说明。本版不自动评价作品画面质量。
- 摄像头与IMU原始行为数据保存到本机场次，不加入内容模型提示词。录像需单独保存；眼动精确识别仍未实现。
- 不以表情、眼动、手势或声学特征推断道德、政治观点、人格、心理状态或录取结果。
- 本版不包含精确语速停顿分析、服务端录音回放、端到端实时音视频考官或已验证的评分可靠性报告。

## 项目结构

```text
public/          页面交互、响应式样式与已有品牌素材
public/rubrics.js 12种目标专业训练量表与独立表达量表
src/catalog.js   学校学院专业目录、官方来源与归属校验
src/exam-library.js 官网考核库、适用范围匹配与来源快照
public/catalog-state.js 共享的三级联动与目标切换规则
src/domain.js    环节、评分标准与数据校验
src/materials.js 材料解析与原件记录
src/app.js       场次、预分析缓存、问答状态、复盘编排
src/ai.js        模型提示词、院校评价与报告编排
src/evidence.js  五状态校验、证据去重、覆盖与质量聚合
src/report-export.js 冻结量表、证据账本及对话的 Markdown 导出
src/store.js     本地 JSON 与文件存储
src/server.js    本机 HTTP 服务、上传、搜索及报告导出
src/llm/         复用的 InterviewPal 模型协议适配器
test/            领域与 HTTP 完整链路测试
examples/        虚构材料，供操作验证
scripts/         JavaScript 语法检查
docs/            产品定义、架构与评分规则
```

## 数据与部署

本版仅绑定 127.0.0.1，面向本机单用户。个人材料、问答、缓存、状态事件保存在被 Git 忽略的 `data/`；环境凭据不入库。未实现多用户认证、生产数据库、云端存储、文件加密及留存删除流程，不能直接作为公网多用户服务使用。
